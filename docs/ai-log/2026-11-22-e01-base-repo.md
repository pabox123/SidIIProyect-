### Conexión a bases de datos
- **PostgreSQL:** Pool nativo `pg` con `POSTGRES_POOL` token, `PostgresService` con `query()`, `transaction()`, `healthCheck()`, `getPoolStats()`. Compatible con local, Supabase, Neon, Aiven (SSL configurable).
- **MongoDB:** Mongoose via `@nestjs/mongoose`, `MongodbService` con `healthCheck()`, `getConnectionState()`, `getDbStats()`. Compatible con local y Atlas.
- **Variables de entorno:** Todo en `.env.example` documentado (PostgreSQL, MongoDB, JWT, bcrypt, puerto, frontend URL).

### Health Checks (`GET /api/health`)
- `GET /api/health` — PostgreSQL + MongoDB
- `GET /api/health/postgres` — Solo PostgreSQL
- `GET /api/health/mongodb` — Solo MongoDB
- Respuesta estructurada con `status`, `info`, `details`, latencia, pool stats, collections count.

### Frontend base
- React 18 + Vite + TypeScript + React Router
- `App.tsx` muestra health check visual en tiempo real (auto-refresh 30s)
- Proxy Vite configurado para `/api` → `http://localhost:3000`
- Estilos CSS modernos con variables, dark theme, responsive

### Scripts de BD organizados
- Copiados `sql/*.sql` → `database/postgres/`
- Copiados `mongodb/*.js` → `database/mongodb/`
- Mantienen nombres originales para no romper referencias de Miguel/Krystal

## (b) Decisiones tomadas

| Decisión | Justificación |
|----------|---------------|
| **NestJS + pg nativo (no TypeORM/Prisma)** | Control total sobre pool, transacciones, y compatibilidad con funciones `SECURITY DEFINER` y `FOR UPDATE` que Miguel implementó en BD. TypeORM/Prisma abstraen demasiado y dificultan llamar `sp_contratar_suscripcion` con bloqueos correctos. |
| **Mongoose (no driver nativo)** | Krystal ya definió modelos con `$jsonSchema`; Mongoose permite definir schemas TypeScript que reflejen esa validación y facilita población/aggregation para E-04/B-02. |
| **`@nestjs/terminus` para health checks** | Estándar de NestJS, integra con Kubernetes/Docker, extensible para custom indicators (PostgresHealthIndicator, MongodbHealthIndicator). |
| **ConfigModule con `registerAs`** | Tipado fuerte, namespacing (`postgres`, `mongodb`, `app`), cache habilitado, carga `.env.local` + `.env`. |
| **Global prefix `/api`** | Convención REST, evita colisiones con rutas de frontend (SPA fallback). |
| **Helmet + CORS + ValidationPipe global** | Seguridad por defecto: headers, origen único (FRONTEND_URL), whitelist/forbidNonWhitelisted en DTOs. |
| **`.env.example` exhaustivo** | Documenta TODAS las variables necesarias (PostgreSQL local/cloud, MongoDB local/Atlas, JWT, bcrypt, pool). Comentarios explican cada sección. |
| **Frontend demo con health check visual** | Permite a Balanta verificar conectividad inmediata sin escribir código; base para B-01. |
| **Estructura `database/` separada** | No mezclar scripts de BD con código de app; Miguel/Krystal pueden versionar sus scripts independientemente. |

## Riesgos conocidos

1. **`bcrypt` en Windows** — Compilación nativa falla sin Build Tools. Mitigación: documentar en README o cambiar a `bcryptjs` temporalmente.
2. **Variables de entorno no validadas al startup** — `ConfigModule` no valida schema; considerar `joi` o `class-validator` en `AppModule` para fail-fast.
3. **Pool pg no cierra conexiones idle en test** — `onModuleDestroy` cierra pool, pero en tests unitarios puede quedar colgado. Usar `--forceExit` en Jest o `afterAll`.
4. **CORS hardcodeado a `localhost:5173`** — En producción cambiar `FRONTEND_URL` en `.env`.
5. **Frontend proxy solo en dev** — En producción, servir `dist/` detrás de nginx/vercel y configurar rewrite `/api` → backend real.
